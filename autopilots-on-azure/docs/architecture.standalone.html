Operating model

A Worker is a named digital colleague with its own identity, role, private state, and tools. Its gateway accepts authenticated activities and manages runtime availability. The agent runtime owns reasoning, tool use, memory, skills, and document work. Foundry supplies model inference; it does not host the agent's compute.

A runtime wrapper adds execution and learning boundaries around the agent loop. Model and tool traffic leaves the runtime directly; the gateway is neither an inference proxy nor a general tool router.

Conversation turns

A user explicitly mentions the Agent User in a group conversation, and the host delivers the activity to the registered Worker endpoint. The gateway does not subscribe to all channel traffic and cannot assume complete group history.

  1. Authenticate before invoking the Worker

    The Agents SDK validates Activity Protocol authentication. The bridge resolves the Worker, caller, and conversation; unsupported or invalid input does not become an agent task.

  2. Reuse state without allowing concurrent writers

    The gateway ensures the runtime is available. The wrapper binds native session context and obtains the execution boundary; the agent runtime reads the appropriate profile and performs the requested work.

  3. Reply through the originating workload

    The bridge delivers the result through the channel. Office comment requests stay in their comment thread. An early HTTP acknowledgement is not a durable queue entry or proof of task completion.

Email and Office notifications reply in their originating workload rather than being redirected to Teams.

Documents

Work IQ handles supported discovery, reading, creation, and comments. For a Word body edit, reviewed Office tools inside the runtime change a private copy, and the collaboration MCP coordinates Graph download, validation, and same-item publication.

Same-item publication preserves the document's identity, sharing, comments, and history. A copy is reported as a different item. The Worker never reports the original as updated when the upload failed.

A locked edit is staged privately for one hour by default. Choosing background publication starts a separate 24-hour retry deadline and retains the file for one further hour for completion/cleanup. Teams actions select retrying the original or sharing a copy; retries do not start another model turn. See the document contract for configuration and receipt retention.

ETag conflicts are not silently overwritten. Attachment content is turn-scoped and excluded from durable learning; pending publication is a separate bounded retention path. External message delivery is not exactly-once.

State and recovery

The profile contains native memory and history, private skills, governed role/candidate skills, learning records, schedules, and working files. A pinned Role Release provides the baseline against which local governed changes are tracked.

A healthy stopped or suspended Sandbox resumes with the same ID. A failed runtime can be replaced while preserving its Data Disk. A profile refresh is a separate governed operation, not an automatic side effect of a new image.

Component reference

Agent 365 channel and identity binding

Channel identity

Each Worker has an Agent Identity and Agent User. Agent 365 binds its endpoint and permissions, then delivers Microsoft 365 activities to /api/messages. The Agents SDK authenticates incoming requests.

Gateway Sandbox

Always awake

The gateway authenticates activities, binds conversations, wakes the agent runtime, consumes Service Bus, and delivers replies. It stays awake for queued and post-acknowledgement work. Model calls and MCP traffic go directly from the runtime.

Runtime wrapper

Runtime-local boundary

The wrapper binds sessions, serializes execution, and applies learning safeguards around the runtime API. It prevents concurrent writers and reports ambiguous interrupted work instead of silently rerunning it.

Agent loop

Agent behaviour

The agent runtime combines role, memory, and skills; calls the model; and selects authorized tools until it can respond. Private learned state stays with the Worker. Reasoning does not run in the gateway.

Loopback MCP identity adapter

Runtime-local authentication

The adapter refreshes tokens for approved MCP endpoints. Autonomous tools use Agent Identity; supported Microsoft 365 calls use the fixed Agent User. It is not human on-behalf-of access or a model proxy.

Collaboration MCP and reviewed Office tools

Private local editing

A loopback MCP wraps reviewed Office tools and Graph publication. It edits a private copy, checks meaning, and validates Open XML. New defects block upload; tooling is built into the runtime image.

Worker Data Disk

Persistent private state

Memory, skills, sessions, cron, receipts, and document staging survive compute replacement. The profile belongs to the Worker, not each caller. Raw documents and private state stay out of shared learning exports.

Service Bus queue and dead-letter handling

Per-Worker queue

The queue carries cron, Dream, and document-retry triggers, never prompts or document contents. The awake gateway receives with PeekLock and settles each message explicitly. Runtime cron sends as Agent Identity; gateway receive and retry send use the gateway managed identity.

Native cron provider

Scheduled work

Schedules stay on the Data Disk. Cron sends the next occurrence to Service Bus; the gateway wakes the agent runtime when due. Proactive delivery requires a previously bound conversation. Scheduling is enabled per Worker.

Observability and correlation

Cross-cutting metadata

Gateway, queue, model, and tool spans report timing, correlation, and usage to Azure Monitor. Default traces exclude prompts and document contents. Foundry registers the external agent; some platform hops retain correlation gaps.

Foundry model inference

Model API

The agent runtime calls Foundry directly through the native provider. Its managed identity and RBAC authorize inference; local authentication is disabled. The gateway is not an inference proxy.

The reference deployment uses the Entra-only public endpoint; the production target adds a private endpoint.

Microsoft-hosted MCP tools

Public HTTPS

Use approved Microsoft-hosted tools, such as Azure DevOps and Microsoft 365 MCP integrations. Configure permissions for each service. Microsoft 365 operations use the approved Agent User flow; other services require their own supported connection.

Existing private MCP

Customer-provided service

Connect to an MCP server already running in the customer network through private routing and DNS. Reuse its approved authentication and permissions; no new MCP host is needed in this solution.

Custom MCP

Optional adapter

Add an ACA-hosted adapter when a backend lacks MCP. It exposes a private MCP interface and reaches backend APIs through the workload VNet and enterprise hub. Use a supported private-ingress hosting configuration.

Microsoft Graph under the Agent User

Deterministic file operations

Graph handles downloads, ETags, guarded uploads, sharing, and supported Excel writes. Calls use the fixed Agent User's approved permissions. Verify the recipient's access before delivering an output link.

Teams and Microsoft 365 entry points

Reference implementation

Personal messages and explicit Agent User mentions are supported entry points. Delivered replies, selected reactions, Mail notifications, and Office comment events have workload-specific handling.

Shared groups are a shared audience. Private per-person delivery and human on-behalf-of identity are not implemented.

Agent runtime

ACA Sandbox

The gateway resumes or reuses agent compute; state survives on a separate Data Disk. One runtime writes the Worker profile at a time. It suspends to Disk after 30 idle minutes and resumes with the same ID.

Model and tool loop

Illustrated runtime behaviour

The agent runtime calls Foundry for reasoning and invokes authorized MCP/native tools as needed. These are separate calls with separate credentials and failure modes. An external tool can be private-network reachable yet still deny access.

The example is a functional sequence, not measured call counts, timing, or an assurance that every request needs every tool.

Locate and download the original

Reference document workflow

Work IQ helps discover the shared item and its meaning. Deterministic Graph access captures the source item identity and ETag and downloads the document into a private Worker workspace. A link alone is not proof of permission.

Edit a private copy

Reference document workflow

Reviewed local Office tools apply only the requested change. Source bytes, excerpts, staged output, edit intent, and operation metadata remain private. These are not stored in Service Bus and are not exported as shared skills.

Verify meaning and package validity

Reference document workflow

Verify the requested semantic change and validate Open XML against the Microsoft 365 target. Existing validation defects are a private baseline; newly introduced defects prevent publication. Package validity alone does not prove that the edit means what the user asked.

ETag-guarded same-item publication

Reference document workflow

Publish to the original item using its source ETag. If the source changed, re-read it. Only reconstructible guarded edits may rebase; opaque transformations fail closed instead of overwriting coauthor changes.

Apply the body update before claiming success in comments or messages. A lock does not justify checking out the document to block other authors.

Deterministic background publication

Reference document workflow / no repeated model call

The gateway schedules document.publish.retry with an opaque operation ID and later invokes a fixed runtime publication API. Bytes, edit intent, source ETag, recipient, and delivery reference stay on the Data Disk.

The checked-in retry choice uses a 24-hour deadline. At expiry or a terminal rebase conflict it produces an explicitly shared copy, not a false “original updated” result. Receipts protect state transitions but cannot make external delivery exactly-once. The duration is an implementation policy, not an Azure limit.

Explicit user choice after a persistent lock

Reference document workflow

Offer reviewed actions: “Keep trying original” or “Send shared copy now”. Authenticated encrypted tokens bind the Worker, user, conversation, operation, and expiry; the gateway consumes actions idempotently. The agent does not invent raw action payloads.

Original item updated

Reference document workflow

A successful same-item write preserves item identity, URL, sharing context, comments, and version history. Record the mutation receipt and report the applied change. When the request originated in an Office comment, reply in that thread rather than an unrelated Teams chat.

Explicitly shared copy

Reference document workflow / distinct outcome

Create a separate Agent User-owned copy and verify the intended user's write permission before delivering its link. An unshareable copy is removed. The response must state that the original was not changed and that the copy has separate comments, sharing, and history.
