Autopilots on Azure · implementation architecture

A thin control plane. A durable Worker.

The approved architecture unifies runtime, gateway, private MCP, public MCP, and generated applications on separate ACA Sandbox Groups and user-assigned identities per Worker. Hermes 0.19.0 uses native Foundry Entra authentication; the MCP identity adapter remains. The gateway stays running, while runtime compute is OnDemand with a durable Data Disk.

03 / RUNTIME

The Sandbox is replaceable. The Worker is not.

The runtime image is immutable and disposable. The profile on the named Data Disk is the durable Worker identity and state boundary.

01 · PROVISION

Create the Data Disk once

The bridge asks the Sandbox Group data plane for the Worker’s named volume. If it does not exist, Azure creates it before the Sandbox.

02 · ATTACH

Mount at /data

The Sandbox mounts the persistent volume. Hermes activates /data/hermes/profiles/<role> and uses its workspace, SQLite state, memories, skills, cron files, and receipts.

Worker ID, Role Release, runtime image, and config revision label the Sandbox. A mismatch replaces compute while reattaching the same disk.

04 / TEAMS

Agent 365 outside. Hermes inside.

Teams never connects directly to the Sandbox. The per-Worker bridge terminates Activity Protocol, establishes the privacy boundary, and translates to a runtime-neutral request.

INTERACTIVE TURN
Teams sends a supported activity

The UI recheck found Hermes in public group @ discovery, not targeted /. No private content was sent; targeted inbound remains unverified rather than universally unsupported.

Agents SDK authenticates ingress

The bridge identifies the Worker, user, conversation type, authorization mode, and private attachment boundary.

Bridge creates, resumes, or reuses compute

Stopped runtimes are resumable; only Failed is recycled. Both native SDK and deployed application resume now preserve the same runtime ID and Data Disk. Application timing includes model work.

Hermes runs the turn

The Gateway owns the session, model calls, tools, memory, skills, and learning transaction.

Bridge returns the activity

Text and reactions use Activity Protocol; Work IQ Teams can also create chats and send messages or files as the Agent User.

PROACTIVE SCHEDULED RESULT
Capture the conversation reference

A user-created schedule is durably bound to its existing personal, group, or channel conversation.

Execute after runtime wake

The running gateway receives the due message; Hermes persists the result on the Data Disk.

Continue the conversation

The bridge uses app-ID continuation when persisted inbound claims are empty.

Require an activity ID

The queue message is acknowledged only after Teams returns a concrete activity ID.

Current boundary

Activity Protocol continuation posts into an existing installed conversation. Work IQ Teams creates a new one-to-one chat, contacts a relevant person, and sends Microsoft 365 files as the Agent User. These are distinct delivery contracts.

Teams conversation is not a lifetime model transcript

ADR 0017 keeps stable per-user memory keys while rotating conversation/thread transcripts hourly. Group transcripts remain shared. Key construction alone does not prove private memory or recall isolation; the tension with the intended privacy requirement remains an open design boundary, not an approved per-user transcript redesign.

05 / INTERACTION SURFACES

Native cards for choices. Sandboxes for applications.

The bridge keeps consequential chat actions deterministic. Rich Hermes-authored code runs in a separate execution boundary with its own identity, URL, and lifecycle.

A16 · ADAPTIVE CARDS

Bridge-rendered Teams interaction

Hermes emits a bounded display, choice, or confirmation request. The bridge owns card JSON, verbs, encrypted user/conversation-bound tokens, expiry, one-time claims, replacement, and continuation. Suggested actions or text cover unsupported delivery paths.

A17 · GENERATED WEB APP

One child Sandbox per app

Hermes writes and tests inspectable source under its private workspace. A fixed tool deploys it to the dedicated generated-app Sandbox Group with deny-default egress, owner scope, quotas, five-minute idle suspend, native 24-hour post-suspension retention, and an Entra participant allowlist.

USER TASK · hermes.cron.fire

Prompt execution with proactive delivery

Revision checks reject stale updates. Pre-fire receipts, Hermes claims, execution leases, bounded delivery receipts, and a required Teams activity ID make redelivery safe.

PLATFORM TASK · system.dream

Same wake path, no agent prompt

A reserved schedule dispatches Dreaming. Fenced phase checkpoints permit completed-response replay; an ambiguous dream_started stops rather than blindly rerunning. Run-now cannot consume the production occurrence.

DOCUMENT TASK · document.publish.retry

Deterministic retry without a model turn

A private Data Disk operation owns staged bytes, ETag, deadline, recipient, and delivery reference. Service Bus carries minimal identifiers. A Teams send accepted before its durable receipt can be repeated after a crash: external delivery is not exactly-once.

07 / IDENTITY

Execution identity is not business identity.

Managed identity proves where code runs. Agent Identity authorizes autonomous application work. Agent User represents the digital teammate for Worker-owned Microsoft 365 resources.

WORKLOAD CREDENTIAL

One user-assigned identity per service role

Runtime, gateway, private MCP, public MCP, and generated-app Groups have separate permissions. Workload identity bootstraps Azure access and federation; it is not the business principal exposed to tools.

AUTONOMOUS PRINCIPAL

Agent Identity

Obtains resource-specific application tokens for custom private/public MCP servers and Service Bus scheduling. Native Foundry inference uses the runtime's managed identity separately. Tool servers validate audience, tenant, issuer, object/client identity, and app role.

DIGITAL TEAMMATE

Agent User

Uses user_fic for licensed Worker-owned Microsoft 365 resources. Mail, proactive Teams, files, Word comments, Excel ranges, and Graph versions are attributed to this identity—not the invoking human.

PRIVATE DOES NOT MEAN UNAUTHENTICATED

Two independent controls

VNet routing and private DNS establish reachability. Entra application authorization still decides whether the Worker may call the MCP server. Incidents is the repository example.

PUBLIC DOES NOT MEAN ANONYMOUS

HTTPS plus exact audience

A public MCP endpoint is internet-routable, but it accepts only valid tenant/issuer/audience claims and the required application or delegated role. Shipments is the repository example.

Managed first, custom only for the product gap

Work IQ remains the preferred surface. The local Graph bridge exists because current managed tools do not edit an existing Word body, expose general Excel range writes, or provide Agent User-attributed same-item upload with ETag conflict protection.

Generic Entra pattern; repository-specific scope names

A custom MCP server has a Microsoft Entra resource application with an identifier URI that becomes the token audience. That resource application exposes application roles for autonomous Agent Identity access and, when needed, delegated scopes for human OBO. The Worker’s Agent Identity service principal is assigned the required application role. The loopback proxy requests the resource <application-id-uri>/.default scope, and the MCP server validates issuer, tenant, audience, calling identity, and role. Incidents.Read.All and Shipments.Read.All are only the example role names used by this repository.

11 / NETWORK

Control plane public. Private data plane private.

The architecture deliberately separates user-facing ingress from private tool reachability. The bridge is not a relay for MCP traffic.

APPLICATION VNET

Private ingress foundation

Express managed environment, Private Endpoint and private DNS for the linked private-MCP Group. No classic Container App workload. Native gateway/public-MCP ports use application-level authentication.

SANDBOX VNET

Worker network interfaces

Delegated Sandbox subnet connects through the Sandbox Group VNet connection. Global peering reaches the private MCP environment; linked private DNS resolves its internal FQDN.

Linking is not a reversible switch

A Sandbox Group's managed-environment link is irreversible; verify the destination before provisioning. Keep egress inspection and system TLS trust through SSL_CERT_FILE and REQUESTS_CA_BUNDLE. Do not bypass certificate checks or expose private tools publicly.

13 / FAILURE MODEL

Durability is explicit, not hopeful.

OnDemand runtime suspension and distributed delivery introduce retries and races. The implementation distinguishes stale, duplicate, interrupted, and delivered work; the gateway itself remains running.

QUEUE

PeekLock + renewal

Complete only after durable execution and required delivery. Retry transient failures; dead-letter bounded terminal failures for operator inspection.

HERMES

Claims + revisions

Schedule revision rejects stale cancellation/update races. Claims and receipts prevent redelivery from rerunning an occurrence.

SESSION CONTEXT

A memory key is not an isolation proof

Hourly transcripts remain shared for a group. Stable per-user keys preserve segmentation intent but do not prove isolation of all memory/recall paths; ADR 0017 remains an open boundary.

DREAMING

Replay a result, not an ambiguous invocation

Phase checkpoints and fencing retain completed responses. An ambiguous dream_started stops for inspection; run-now remains separate from the production occurrence.

TEAMS

ACK does not end the gateway's work

Gateway auto-suspend is disabled for detached completion and Service Bus receive. The bridge owns both temporary-eyes actions and executes the agent's semantic reaction. Runtime compute remains OnDemand.

PRIVATE INGRESS

Express is a network boundary, not Worker compute

A linked managed environment with Private Endpoint/private DNS gates the private MCP Sandbox. Group linking is irreversible. No classic MCP Container App or Foundry Hosted Agent compute is required.

SANDBOX

Replace compute, retain disk

Config/image/identity label drift replaces the Sandbox. Worker state remains on the named Data Disk.

DOCUMENT VERSION

Baseline, validate, then publish

Microsoft 365-targeted Open XML validation records source defects before editing. Unchanged legacy errors may remain; any error introduced by Hermes blocks upload. ETag conflicts never overwrite human work.

OFFICE LOCK

Original first, useful fallback

A validated 423 Locked edit remains in bounded private storage. Teams offers retry-original or a shared copy; a Word comment returns the exact proposed content, rationale, and explicit not-applied status in the same thread.

PRIVATE FILE

Cleanup is part of the transaction

Downloads remain under one private workspace. Success, cancellation, validation failure, terminal failure, or bounded pending-operation expiry deletes the staged bytes and edit intent.

NOTIFICATION

Workload-local and idempotent

Email and Office notifications reuse /api/messages, stable workload IDs, and persistence-disabled turns. Responses stay in the originating workload; Word retries require a fresh explicit mention.

OBSERVABILITY

Correlated execution, native-platform parent gap

All 49 reviewed native parents match; 105 audited spans contain allowed metadata. A local control preserved its supplied parent, while fresh uninstrumented urllib inside the gateway Sandbox changed it. This isolates Sandbox-origin egress, not ingress alone or exporter loss. TraceId survives; platform intermediate parents are absent from AppInsights. Exact proxy implementation is unidentified. No custom trace headers, fake parents, or egress bypass. Registration remains external metadata, not Hosted compute.

CORRELATION LIMIT

Missing handoff must stay visible

Gateway executor threads lose context; a short-lived local lease keyed by a hashed native session carries metadata only. Explicit session APIs can correlate; /v1/responses creates its own session and is marked autopilots.trace.correlation=missing. Interrupted leases require restarting the Hermes runtime wrapper/native gateway before reusing that session.

DEPENDENCIES

Locks make risk reproducible, not absent

Hermes 0.19.0 uses Python/npm locks and weekly Dependabot. All four protected-feed image builds completed; both MCP Docker paths use frozen uv locks. Private/public local MCP tests (6/1) passed. Two inherited high-severity image-size findings have no published fix.

MCP DEPLOYMENT

Real tool spans and bounded service recovery

Hermes returned expected service IDs and SHIP1001–SHIP1003; the exact morning private/public tool spans are ingested. Terminal Failed gateway/MCP replacement now passes 19 operator tests. A real healthy private-MCP redeploy preserved its ID and health 200; that is reuse, not live failed recovery. Unchanged matching Stopped/Suspended services retain IDs. No image/endpoint rollout was needed. Tool execution is not independent VNet-route or MI-authentication proof.

CREDENTIAL LIFECYCLE

Redeployment needs no registry login

Repeated live MCP deployment reused Sandbox IDs without registry login, verified with a fail-if-called guard. All ten workload AcrPull assignments were removed and ACR admin is false. Native SDK b4 MI conversion still fails; accepted transient Entra credentials are deployment-only. MCP reuse does not establish runtime/gateway behavior. Accepted ADR 0021 →

LEARNING

Four response cases passed; Dream found no changes

Real Hermes 0.19 Role 3.2/3.3 comparison scored 3/4 versus 4/4, zero regressions. These were four operator-authored response-only cases, not an agent-proposed packet. Hermes 2's ad-hoc Dream completed with zero records/no packet and unchanged production cron. Ad-hoc Dream completed at phase prepared, success=true, recordCount=0, packet=null, with production cron unchanged, scheduled count 1, DLQ 0. Separate native SDK and final application same-ID/Data-Disk resume checks both passed. Automatic eight-hour idle suspension remains unverified.
