Private and shared state

Private memoryUSER.md and MEMORY.md retain compact preferences and durable working facts.
Private skillsskills/private/ stores project-, customer-, or assignment-specific playbooks.
Role skillsskills/role/ starts from a reviewed Role Release and can receive governed local patches.
Candidatesskills/candidates/ holds generalized capabilities proposed locally for later review.

Raw Work History stays private. Only eligible role/candidate changes enter a Learning Packet. Generalization means removing private facts, not just moving the same text into another directory.

Classification policy · Enforced learning boundary

  • Fresh session: active SOUL.md and compact memory provide starting context.
  • Relevant task: skill names and descriptions allow discovery; full instructions load when selected.
  • Recall or Dream: session search retrieves relevant Work History instead of injecting the entire database.

Memory files and private playbooks are Worker-wide. Session keys identify the caller, but native group transcripts are shared and rotate hourly by default. A user-specific key does not create a separate memory store.

Native runtime setup · Profile layout · Conversation boundary

Local acceptance

Hermes uses native memory and skill tools. An explicit /learn <instruction> focuses one transactional turn on an adaptation. The model proposes the skill change and its provenance; the runtime independently derives what changed on disk.

A useful local improvement can remain active in this Worker before any shared release. That local acceptance neither exports private data nor grants permission to publish the skill to other Workers.

Turn routing and learning instructions · Turn reconciliation

  1. ReviewInspect outcomes, corrections, skills, and relevant history.
  2. ClassifyKeep private context private; generalize reusable behavior.
  3. ReconcileAccept valid changes or retain nothing.

The reviewed Dream Role Skill guides reflection. A system schedule invokes it through the gateway and Service Bus. Durable fenced phases recover completed responses; an unknown interrupted model outcome stops rather than triggering a blind replay. Ad-hoc execution does not consume the production occurrence.

Dream instructions · Durable coordinator

  1. Snapshot under a lease

    Recover pending work and capture the governed/private skill state before the turn.

  2. Match change to provenance

    Derive the real diff, validate classification and privacy, and require matching evidence for each governed artifact.

  3. Commit or restore

    Accept the governed change set atomically with runtime-derived identity and hashes. Any rejection restores the entire governed snapshot and appends no records.

Provenance schema 3.0 permits create or patch on exactly one SKILL.md per artifact. artifactPath names the skill directory; artifact.changedFiles names that directory's one skill file. Scripts, references, auxiliary files, and deletion are outside the governed export lane.

The runtime, not the model, appends learning/records.jsonl. Attachment-bearing turns cannot turn document content into durable memory or skills.

Transaction implementation · Provenance schema

Approval and release

Packet preparation reconstructs eligible changes from the Role Release baseline to the current skill hash. It includes each linked provenance record, the final skill file, Worker/release attribution, and the governed-state hash. The digest binds the packet's exact content.

Each agent-proposed scenario declares input, setup assumptions, scope, expected observable outcomes, and acceptance criteria. Criteria operate on response.text using contains, not_contains, or equals; they are data, not executable test scripts.

Privacy checks cover both skill text and test proposals. Raw memories, history, private skills, workspace files, credentials, and logs are excluded.

Source

Packet reconstruction · Scenario contract

The runtime verifies an Ed25519-signed receipt against the packet digest, Worker, release commit, and governed-state hash. A signature over a different or stale packet cannot authorize export.

Approve exportAllows the exact reviewed packet to leave the Worker; it does not approve merging or release.
Reject and refreshRecords the signed rejection and permits discarding those governed local changes during the controlled refresh.

An unreviewed packet must not be treated as approved simply to unblock a refresh.

Receipt verification and refresh guard · Operator approval flow

Agent-written scenarios make the intended improvement inspectable. Reviewers still need independent regression cases: otherwise the author can describe a skill and the easiest test for that same description.

The evaluation script performs real model calls for both versions and records case outcomes and usage. Missing usage is an error, not zero cost. Results need the case set, model/settings, baseline, candidate, and packet binding to be interpretable.

The current runner injects selected skill text into the prompt and asserts response text. It does not measure native skill discovery, live MCP workflows, tool side effects, or general task success. Agent-proposed and independent cases must stay distinguishable; neither a signature nor a higher pass rate broadens the tested scope.

Evaluation runner · Evaluation contracts

  1. Review packetCheck privacy, evidence, skill quality, and role alignment.
  2. Publish releasePin the reviewed Role Blueprint to an immutable commit.
  3. Refresh WorkerResolve local governed changes, then install the selected release.

A forward-only refresh preserves private memories, private playbooks, and Work History. It replaces Role Skills and archives the prior release's candidates and provenance. It does not copy another Worker's private profile or silently merge unreviewed local edits.

Component reference

Work turn

Ordinary or /learn

Native memory and skill tools can change the profile during ordinary work. An explicit /learn <instruction> focuses one transactional turn on an adaptation. Attachment-bearing turns cannot turn document content into durable memory or skills.

Dream

Scheduled reflection

A system schedule delivers system.dream through Service Bus and the gateway. The reviewed Dream Role Skill reviews, classifies, and reconciles. Durable fenced phases recover completed responses; an unknown interrupted outcome stops for inspection.

Learning transaction

Runtime-owned boundary

The runtime snapshots governed and private skills under a lease, derives the real diff, and matches each governed artifact to provenance schema 3.0. It commits atomically or restores the whole snapshot and appends no records.

Worker profile

Data Disk

USER.md, MEMORY.md, skills/private/, skills/role/, skills/candidates/, learning/records.jsonl, sessions, and schedules. Private layers never enter a Learning Packet.

Learning Packet 2.0

Digest-bound export candidate

Reconstructs eligible role and candidate changes from the Role Release baseline, with provenance, final skill text, attribution, the governed-state hash, and agent-proposed scenarios. Privacy checks cover skill text and scenarios.

Signed approval

Ed25519 receipt

The runtime verifies the signature against the packet digest, Worker, release commit, and governed-state hash. Approve export lets the exact packet leave; reject and refresh permits discarding those local changes.

Collective review

Central workflow

Verifies packet digests and receipts, compares packets from several Workers, and judges which role skills generalize. Private skills and raw history are not inputs.

Promotion pull request

Draft pull request with agentic gates

GitHub Agentic Workflows triage the change and review privacy, role alignment, evidence, and skill quality. Evaluation results inform the reviewer; a human merges.

Role Release

Pinned Git commit

A semantic version pinned to an immutable commit of the Role Blueprint. It becomes the baseline for later Learning Packets.

Worker refresh

Forward-only

Requires local governed changes to be exported or rejected first. Replaces role skills, archives prior candidates and provenance, and keeps private memory, private skills, and Work History.
