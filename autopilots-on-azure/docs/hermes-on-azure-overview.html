One worker, durable continuity

  1. Teams / Microsoft 365A message or notification reaches the worker.
  2. Gateway SandboxAuthenticates, routes, and wakes execution.

Each Worker has its own Agent User, private Data Disk, and pinned Role Release. The example role is a junior project manager: handle assignments, inspect incidents and shipments, collaborate on documents, and retain useful working context.

The gateway stays awake to handle post-acknowledgement work and receive scheduled messages. It starts or resumes the runtime when needed. This is not whole-system scale-to-zero.

Tools act under the worker's identity

  • Work IQ MCP: mail, calendar, Teams, files, and Office operations exposed by the managed service.
  • Custom MCP: private incidents and public shipments endpoints, both protected by Entra authorization.
  • Document adapter: Agent User Graph operations and local document tools for same-item edits, ETag conflicts, and format validation.
  • Generated apps: a separate Sandbox Group serves applications the Worker builds; its identity does not inherit the agent's tool permissions.

The model calls Foundry directly through Hermes' native Entra provider. Foundry also registers the external agent and surfaces monitoring; it does not host this runtime.

Managed identities authorize infrastructure access. Agent Identity authorizes autonomous business-tool calls. Agent User represents the Worker in Microsoft 365, with its own access and attribution. A Teams request does not automatically delegate the human's permissions.

In a group, the Worker uses the shared conversation. A user-keyed memory mechanism is not full per-user isolation. Private targeted replies inside a group are not implemented by this demo; use the ordinary group interaction without promising a hidden answer.

Local adaptation, reviewed sharing

  1. Adapt locallyA turn or Dream proposes a skill change.
  2. ReconcileThe runtime validates the actual diff and evidence.
  3. Approve exportA signed receipt binds an exact Learning Packet.
  4. Review and releaseEvaluation and review precede shared adoption.

Private memories, session history, and project playbooks stay with the Worker. A Learning Packet carries eligible skill changes, provenance, and agent-proposed test cases. Other Workers receive the improvement only through a reviewed Role Release.

Learning contract · Packet and approval implementation

Hermes stores user schedules on the Data Disk. Service Bus holds minimal wake-up messages; the gateway receives them and invokes the runtime. Dream reflection uses the same mechanism with a bounded system task.

Receipts and fenced execution phases make retries explicit. A completed Dream response can be recovered; an interrupted model run with an unknown outcome is not blindly repeated. Finding nothing worth retaining is a valid result.
