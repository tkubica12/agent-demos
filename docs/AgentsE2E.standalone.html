Five stages of agent solutions

From answers
to shared expertise.

Beyond autonomy: continuity and transferable capabilities.

This is a working model, not a product ranking or a mandatory path to maximum autonomy. Choose the simplest stage that serves the purpose.

  1. ChatbotAnswers or drafts a response. A person takes the next action.
  2. WorkflowRuns a predefined process. AI can handle individual steps.
  3. Personal workerChooses an approach, uses tools, completes the assigned task, and stops.
  4. Digital colleagueSustains a role and state, responds to events, and learns from experience.
  5. Shared expertiseTurns expert practices into reusable skills for other teams.

A worker delivers a result; a digital colleague continues serving the team under its own identity and defined boundaries. Shared expertise transfers capabilities, not team-local data, permissions, or preferences. It is not necessarily more autonomous than a colleague.

Architecture: platform

A model proposes.
A system acts.

Every stage needs a runtime, connections, control, and operations.

Every stage must address runtime, connections, control, and operations. This does not require every product: the platform supplies some layers, and their scope matches the risk. The model proposes actions; the runtime manages context, state, tools, approvals, and stopping conditions.

  • Copilot Studio: low-code agents and business workflows.
  • Microsoft Foundry: managed prompt agents or hosted custom code.
  • Microsoft Agent Framework, LangGraph, OpenAI Agents SDK: code-first control over orchestration.

Start with one focused agent. Add a specialist only when task boundaries or evaluations justify it. A Responses API call is not an entire enterprise operating model.

Source

Foundry agent types and runtime choices.

Govern access,
not just models.

  • Foundry: projects and model choice
  • APIM: access, routing, budgets
  • Prove the traffic actually passes through

Foundry supplies projects, model access, and development tooling. Azure API Management (APIM) provides an AI gateway for authentication, routing, quotas, and telemetry. Choose models by measured quality, latency, cost, and data boundaries, not brand alone.

Foundry's portal now supports creating or reusing APIM; it is no longer merely planned. The integration is documented as preview. Existing instances need a supported v2 tier, the same tenant and subscription, and suitable network access. Verify enforcement, including requests that might bypass the gateway.

Sources

AI gateway capabilities; Foundry integration requirements.

Managed hosting
still needs boundaries.

  • Prompt agents: configuration
  • Hosted agents: code in isolated sessions
  • Self-hosting: your operational responsibility

Copilot Studio hosts its agents. Foundry prompt agents run from configuration; hosted agents run your code with managed endpoints, identity, scaling, and session state. Hosted agents are generally available and use per-session VM-isolated sandboxes.

Use Azure Container Apps, AKS, or another host when platform constraints require it. You then own deployment, recovery, isolation, and telemetry. For long-running work, distinguish saved conversation history from recoverable execution; retries must not duplicate business actions.

Architecture: connections

Standardize connections.
Authorize every action.

  • MCP connects tools
  • A2A delegates to agents
  • Neither replaces authorization

Model Context Protocol (MCP) connects tools and resources; Agent2Agent (A2A) connects independent agents for delegated tasks. Ordinary API calls remain appropriate. Foundry Toolboxes group tools behind a managed MCP endpoint; APIM governs traffic, while a catalog helps discovery.

Protected HTTP MCP uses OAuth; Microsoft Entra can provide identity, but is not mandated by MCP. Validate tokens, audience, permissions, and business rules at the resource. A gateway cannot infer missing business authorization. Require approval for consequential writes and make retries idempotent.

A2A and MCP; MCP authorization; Toolboxes.

Useful context
beats more context.

  • Work IQ: people and work
  • Foundry IQ + Fabric IQ: documents and business meaning
  • Web IQ: current external context

  • Work IQ: people, collaboration, and work context across Microsoft 365.
  • Foundry IQ: shared knowledge bases and agentic retrieval over institutional content, built on Azure AI Search.
  • Fabric IQ: business entities, relationships, and governed semantic models.
  • Web IQ: fresh context from the public web.

These are complementary capabilities, not one interchangeable MCP service. Preserve source permissions, freshness, and citations. Memory stores evolving context; it is not an authoritative knowledge base. Set retention and deletion rules.

Foundry IQ mixes GA and preview by API version; portal agentic retrieval remains preview. Fabric's IQ workload and ontology are preview. Check the exact component, not the umbrella brand.

Sources

Microsoft IQ; Foundry IQ; Fabric IQ.

A channel delivers.
It does not govern.

  • Teams, Microsoft 365 Copilot, web
  • Transport and identity must both work
  • Channel SDK is not governance SDK

Foundry publishing to Teams and Microsoft 365 Copilot is GA. Copilot Studio provides managed channels; custom integrations can use the Microsoft 365 Agents SDK and Activity Protocol.

The Microsoft 365 Agents SDK handles conversational delivery and state. The Agent 365 SDK adds governance-related capabilities to an existing agent; it does not host or orchestrate it. Verify streaming, attachments, approvals, and delegated authentication per channel. A public endpoint is not permission to access enterprise data.

Architecture: control and trust

Identify the actor
before granting access.

  • Delegated user access
  • Agent identity for autonomous work
  • Agent user accounts remain Frontier preview

Use delegated access when acting for a signed-in user, including on-behalf-of (OBO) token exchange where supported. Autonomous work uses the agent's own approved permissions. Entra agent identities provide an identifiable, governable actor; blueprints define a reusable identity foundation.

Set an accountable owner, least privilege, consent, and revocation. An agent identity is not an agent user account with a mailbox. Those accounts and associated notifications remain Frontier preview; they are neither merely a future idea nor universally available.

Sources

Entra agent identity; Identity modes and Frontier restrictions.

An inventory is only
the starting point.

  • Agent 365: organizational control
  • Foundry: development and operation
  • Registration alone does not activate every protection

Agent 365 has been GA since May 2026. It provides organizational inventory and governance, integrated with Entra, Purview, and Defender. Foundry supplies developer and operational controls; these roles complement each other.

Choose built-in integration, registry synchronization, or Agent 365 SDK capabilities as needed. Appearing in an inventory does not automatically enable tooling, telemetry, or enforcement. Check licenses and integration coverage. Every agent needs an owner, an approved purpose, and a way to block or retire it.

Data protection
must be configured.

  • Include agents in relevant policies
  • Enforce permissions at retrieval
  • New content does not automatically inherit labels

Purview provides audit, classification, data loss prevention (DLP), and compliance capabilities for supported paths. Include agent instances in the relevant policies; custom applications need the appropriate integration.

Agent 365-created content does not automatically inherit source sensitivity labels. Encrypted files require explicit VIEW and EXTRACT rights for the agent instance. Test both permitted access and denied access, including retrieval results, generated files, and telemetry.

Sources

Purview coverage and limitations; Custom application integration.

Detect attacks.
Bound the damage.

  • Guardrails filter risky content
  • Defender can block supported runtime actions
  • Authorization and approvals remain essential

Foundry guardrails help mitigate unsafe content and prompt injection. Defender can also inspect and block supported actions before execution. Its default cloud rule audits; blocking requires custom rules. Copilot Studio and Foundry coverage includes preview features.

Agent 365 tool protection depends on supported Work IQ MCP integration. Unsupported paths are not covered. Treat retrieved content as untrusted, restrict tool permissions and outbound access, and require human approval for high-impact actions. Filters do not replace business authorization or safety evaluations.

Sources

Defender coverage and audit/block behavior; Foundry safety controls.

Architecture: operation and improvement

Trace the work.
Measure the outcome.

  • Correlate model, tool, and agent calls
  • Track quality, latency, and cost per completed task
  • Protect telemetry as sensitive data

Use OpenTelemetry to correlate agent, model, and tool calls with version and outcome. Foundry integrates with Application Insights; Agent 365 SDK emits telemetry for governance. Match instrumentation schemas to the receiving service rather than assuming exporters are interchangeable.

Track completion, escalation, failure rate, latency, and total cost per successful task, including tools and compute. Minimize sensitive content and set retention. Governance dashboards are not a substitute for engineering access to traces.

Sources

Trace evaluation and schema requirements; Agent 365 telemetry.

Evaluate actions,
not eloquence.

  • Task completion and correct tool use
  • Permission boundaries and adversarial inputs
  • Regression gates before release

Maintain representative cases with expected outcomes, allowed actions, and failure criteria. Check grounding, tool arguments, permission boundaries, prompt injection, recovery, latency, and cost. Combine deterministic checks with calibrated model judges and human review.

Copilot Studio's standard harness supports test-set evaluations; Foundry offers built-in and custom evaluators, including task completion and tool-call accuracy. Evaluate before deployment and sample production traces afterward. Agent Optimizer is preview; automatically generated improvements still need independent regression gates.

Sources

Foundry evaluations; Optimizer preview; Copilot Studio evaluations.

Ship a tested system,
not just a prompt.

  • Version code, context, tools, and evaluations
  • Review coding-agent changes before deployment
  • Release gradually; keep rollback ready

Version prompts, models, tool schemas, skills, knowledge configuration, code, and evaluation sets. Use Power Platform solutions and pipelines for Copilot Studio; use infrastructure as code and SDK/API deployment for Foundry. Promote tested versions, monitor changes, and retain rollback.

Coding assistants increasingly span implementation, deployment, and evaluation; Foundry Dev Pack bundles tooling for that workflow. Generated changes still require review and tests.

Retirement notice

Foundry's visual workflow designer and in-portal execution retire on 1 December 2026. Use Agent Framework for new code-first orchestration; hosted execution remains supported. Scope and migration paths.
