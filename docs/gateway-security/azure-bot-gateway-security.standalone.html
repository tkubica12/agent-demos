Verify Connector tokens.

Enforce the classic Connector profile at the edge. Retain Microsoft Agents SDK validation and application authorization in the gateway.

JWT / SDKClassic Connector profile
Crypto/timeBearer JWT; RS256, valid exp/nbf. Trusted metadata: https://login.botframework.com/v1/.well-known/openidconfiguration; use its jwks_uri and refresh keys.
issExactly https://api.botframework.com: the Connector issuer, not your Entra tenant. Do not require the native Agent 365 tid/azp profile.
audExactly the bot's MicrosoftAppId from Azure Bot Configuration / its app registration. Stable for that registration's lifetime; per-bot isolation requires distinct app IDs.
Channel/URLSDK: match the token's service-URL claim to activity serviceUrl; check signing-key channel endorsements where required. Keep these classic checks separate from native Agent 365 behavior.

Tenant isolation: valid Connector authentication, including aud=MicrosoftAppId, binds delivery to your bot, not the Teams conversation's tenant. After authentication, enforce a tenant allowlist in the gateway using channelData.tenant.id; reject missing or unapproved tenants before bot logic, then authorize users/operations. Unlike native Agent 365, this is activity metadata, not a customer-tenant tid claim in the Connector JWT.

Only the edge exposes messages

HTTPS/443, POST /api/messages; backend ingress only from the edge. Require JWT validation, not a regex. Edge egress: login.botframework.com:443 for metadata/JWKS. Bound body size, rate, concurrency and queues.

Teams IPs are not a channel contract

Optional Teams-only IP filter: 52.112.0.0/14, 52.122.0.0/15. Shared ranges neither identify your tenant nor cover other channels. Production Bot Service inbound IP allowlisting is unsupported. Handle IPv6 and trusted proxy sources explicitly.

Sending uses outbound HTTPS

Gateway to login.microsoftonline.com:443 for single-tenant bot tokens, login.botframework.com:443 for validation, and validated serviceUrl:443 for replies/proactive sends. For outbound restrictions on this serviceUrl, see the proxy rule below. Cache current context; approve extra destinations only for enabled features.

Agent backends remain private

Gateway to Service Bus Private Endpoint asynchronously and a private HTTP(S) agent endpoint; private DNS + VNet routing. Only the agent calls MCP. Verify Sandbox private publishing separately from ordinary Container Apps Private Link.

Optional Teams outbound proxy rule: smba.trafficmanager.net:443, optionally path /{geo}/<TENANT_ID>/v3/* with L7/TLS inspection. This is routing, not authorization; URLs can change. Sandbox egress supports similar rules. Other channels need separate destinations.
